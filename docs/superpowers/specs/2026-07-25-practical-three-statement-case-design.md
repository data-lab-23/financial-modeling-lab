# 実務案件型・財務三表モデリング教材 改修設計

## 目的

国内の事業会社、金融機関、FAS、投資銀行、PEの実務担当者が、資料受領から財務三表モデルの作成、レビュー、引継ぎまでを一つの架空案件で学べるサイトに改修する。

最初の成果はValuationではなく、根拠資料から5年間の財務三表モデルを作成し、Base / Upside / Downsideを切り替え、提出可否を判断できる状態とする。

## 採用方針

既存ページを大量に増やさず、共通の製造業案件を主要8ページに通す「共通案件型」を採用する。

- 対象読者：国内事業会社の経営企画・M&A担当者を主対象とし、FAS・投資銀行・PEの若手にも利用できる内容
- 共通案件：東都精密工業株式会社（架空）、B2B製造業、3月決算
- 単位：百万円
- 実績基準期：2025年3月期
- 予測期間：2026年3月期から2030年3月期
- シナリオ表記：Base / Upside / Downside
- 編集名義：Finance Modeling Lab 編集部
- 配布形式：会員登録不要のExcelファイル

売上高は製品A（量産部品）と製品B（高付加価値部品）、国内と海外に分解し、数量と平均販売単価から計算する。費用、運転資本、設備投資、借入金まで同じシナリオへ連動させる。

### シナリオ

- Base：現在の受注状況と会社計画を基礎とする
- Upside：販売数量、製品構成、設備稼働率が改善する
- Downside：需要減少、原材料価格上昇、在庫回転悪化を反映する

## 共通部品

実務解説を再利用する表示部品を設ける。部品は工程上の位置、受領資料、成果物、Excel実装、確認項目、レビュー指摘を表示し、ページ本文の重複を抑える。

共通案件の数値、資料、工程、品質判定は単一のTypeScriptデータ定義からページと検証スクリプトへ供給する。Excel生成も同じ定義を参照し、サイトとExcelの数値不一致を防ぐ。

## 品質判定

提出可否は次の3段階とする。

- Ready：主要確認項目を通過し、そのまま提出可能
- Ready with caveats：軽微な未解決事項を明示したうえで提出可能
- Not ready：意思決定に影響する不整合があり提出不可

指摘事項の重要度は次の3段階とする。

- Critical：財務三表不一致、参照切れ、重要資料との不一致
- Major：重要前提の根拠不足、シナリオ未連動、計算方法の誤り
- Minor：表示形式、注記不足、軽微な構造改善

最低限、財務三表、現預金、固定資産、借入金、利益剰余金、受領資料、シナリオ、数式エラー、前提根拠、未解決事項を確認する。

## 実装順序

1. 共通案件データと静的検証を作る
2. 共通の実務解説部品を作る
3. 主要8ページへ適用する
4. 受領資料パックと完成モデルを生成する
5. ダウンロード一覧と学習導線を更新する
6. 言語、静的表示、Excel、リンク、ビルドを検証する
7. GitHubへ反映し、GitHub Pagesの公開結果を確認する

## 効果測定

既存のアクセス解析を利用し、新しいバックエンドは追加しない。

- 学習ロードマップへの遷移
- 受領資料パックのダウンロード
- 完成モデルのダウンロード
- 各工程から次工程への遷移
- リクエストフォームへの遷移

## 完了条件

- 主要8ページが同じ案件と工程を参照している
- 各ページに受領資料、成果物、Excel実装、確認項目、レビュー指摘がある
- 受領資料パックと完成モデルがサイトからダウンロードできる
- 共通案件の主要数値がページとExcelで一致する
- 完成モデルにBase / Upside / Downsideと品質確認がある
- 受領資料から主要モデルセルまで追跡できる
- 既存の日本語表記方針と許可英語を維持する
- 静的検証、Excel検査、言語検証、ESLint、Next.jsビルドが成功する
- GitHub Pages上で主要ページとExcelのHTTP応答を確認できる
